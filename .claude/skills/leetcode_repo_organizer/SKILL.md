# Skill: 算法代码仓库整理规范

该 skill 用于统一整理当前算法仓库中的代码结构，包括：

- 调整目录结构
- 统一文件命名
- 按题目创建独立文件夹
- 补充题解 markdown 文档

---

## 整理目标

将仓库中零散的算法代码整理为结构统一、可维护、便于检索的形式。

每一道题必须满足以下结构：

- 一个独立文件夹
- 文件夹名称包含题号和题目名称
- 文件夹中包含：
    - 代码文件（Java）
    - 一个 markdown 文档（用于记录思路）

---

## 文件夹命名规范

每道题对应一个文件夹，命名规则如下：

- 格式：lcXXX_problem_name
- 示例：
    - lc001_two_sum
    - lc015_three_sum
    - lc146_lru_cache

命名规则说明：

- lc 表示 LeetCode
- XXX 为题号，必须补齐三位（不足补 0）
- 题目名称使用小写英文
- 单词之间使用下划线连接
- 禁止使用空格或驼峰命名

---

## 文件结构规范

每道题的目录结构如下：

- lcXXX_problem_name/
    - lcXXX_problem_name_01.java
    - README.md

说明：

1. Java 文件名必须与文件夹名称完全一致
2. Java 文件夹末尾的编号表示第几次写这道题
3. README.md 用于记录：
    - 解题思路
    - 核心算法
    - 时间复杂度 / 空间复杂度
    - 易错点
    - 复盘总结

---

## 代码文件命名规范

Java 文件必须满足：

- 与文件夹同名
- 包含题号
- 使用下划线命名
- 末尾带编号，没有同名文件就是01，有同名文件就是最大的编号+1

示例：

- lc001_two_sum_01.java
- lc001_two_sum_02.java
- lc053_maximum_subarray_01.java

---

## README.md 内容规范

每道题必须生成一个 README.md，建议包含以下内容：

- 题目名称 + 题号
- 题目链接（可选）
- 解题思路（核心逻辑）
- 关键点分析
- 时间复杂度与空间复杂度
- 易错点
- 复盘或优化思路（可选）

内容应简洁清晰，避免冗长描述。
只需要生成大纲，内容由我自己填入。

---

## 整理规则

在执行整理任务时，必须遵循以下规则：

### 1. 必须重构为“一题一文件夹”

禁止：

- 多题放在同一文件中
- 所有代码堆在同一目录

---

### 2. 自动识别题号

如果代码文件中包含 LeetCode 题号：

- 提取题号
- 按规范补齐三位数字

如果无法识别题号：

- 保留原文件名
- 但仍需放入符合结构的文件夹

---

### 3. 自动规范命名

需要做以下转换：

- 大写 → 小写
- 空格 → 下划线
- 驼峰 → 下划线风格

示例：

- TwoSum.java → lc001_two_sum.java
- LRUCache.java → lc146_lru_cache.java

---

### 4. 保持代码内容不变

整理过程中：

- 不修改算法逻辑
- 不重写代码
- 仅调整结构与命名

---

### 5. 补充缺失的 README.md

如果某题没有 markdown 文件：

- 自动创建 README.md
- 填写基础结构（可留空内容占位）

整理后结构：

    - lc001_two_sum.java

- lc146_lru_cache/

    - README.md

---

## 注意事项

- 所有整理操作必须是“结构优化”，不是“代码重写”
- 不得引入额外无关文件
- 保持仓库整体风格一致
- 优先保证可读性与可维护性

---

## 总结

该 skill 的核心目标是：

- 统一命名规范
- 建立清晰目录结构
- 强制一题一目录
- 为每题配套思路文档

所有操作应围绕“提升仓库可读性与面试复习效率”展开。
